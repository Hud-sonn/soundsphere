## Why

User request: Blend (collaborative playlists) with invite via share link, saves in user's Library + Home, tap to see who added a song (reusable `UserInfoSheet`), dedicated `Create Blend` button like Spotify plus long-press `Make Blend` for existing, history fill vs fresh choice, updating via polling + in-app notifications (no webhook), plus the `20` cap + `tombstone` delete fix, `500` history FIFO, `2000` liked / `500` per-playlist / `200` follows caps, `600/300` rate limits, and double-project isolation (best) with same `JWT_SECRET` so the same `Authorization: Bearer` works on both hosts.

## How to use

1. **Library → Playlists → Create Blend** (second FAB, `144dp` above `+`) → name → `Fill from history` (adds 20 recent `event` songs) or `Start fresh` → opens `local_playlist/{id}` (`Blend • Collaborative` pill). Shares like normal `Invite to Blend` (long-press → `Make Blend` for existing) → copy `https://api.soundsphere.name.ng/share/playlists/{token}`.
2. Recipient opens link → `SharedPlaylistScreen` shows `Join Blend` (not just `Play`) → tap → `POST /share/{token}/join` → saved as `isCollaborative=true` → appears in **Library** (`• Blend`) and **Home → Blend**.
3. Inside a Blend, each track shows `Added by @name` → tap → `UserInfoSheet` (reusable). Cover edit (`LocalPlaylistHeader` pick) uploads to `Cloudinary` `soundsphere/blends` and syncs `cover_url` to all collaborators via `PUT` + next `pull`.
4. When a member adds a song (`POST /tracks` with `added_by`), the server inserts `notifications` for the other members; the app polls `GET /user/notifications` every 30 s and can show a badge/toast.
